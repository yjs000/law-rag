# Web E2E 검증 명세

## 목적

배포된 Energy Law 웹을 실제 사용자의 조작 순서로 검증한다. 최우선 기준은 정상 질문이 검색, AI 답변,
근거 원문 확인까지 끊김 없이 완료되는 것이다. 정상 흐름이 모두 통과하기 전에는 경계 흐름의 편의성
개선을 우선하지 않는다.

## 대상

- 배포 URL: <https://law-rag-web.vercel.app/>
- 기본 뷰포트: 1280px, 430px, 375px
- 기본 정상 질문:
  - `전기저장시설을 설치할 때 적용되는 화재안전 기준은 무엇인가요?`
  - `전기사업 허가를 신청할 때 제출해야 하는 서류는 무엇인가요?`
  - `전기사업법 제7조 제1항은 어떤 허가를 규정하나요?`
- 개인정보나 실제 사건 자료는 입력하지 않는다.
- 계정 삭제는 전용 테스트 계정에서만 수행한다.

## 공통 합격 조건

- 정상 흐름의 Network 탭에 예상하지 않은 `4xx` 또는 `5xx`가 없다.
- 사용자 동작 한 번에 질문 실행이 하나만 생성된다.
- 중단된 요청은 취소 상태일 수 있지만 후속 `500`을 만들지 않는다.
- Console에 uncaught exception, hydration 오류, React key 오류가 없다.
- 오류 후에도 입력창, 새 질문, 로그인 등 복구 수단이 남는다.
- 답변의 핵심 주장과 체크리스트 인용이 실제 원문 카드로 연결된다.
- 각 완료 항목은 실행 일시, 환경, 결과, Network/Console 관찰 및 필요 시 스크린샷을 증거로 남긴다.

## P0 정상 흐름

- [ ] 첫 진입: 환영 화면, 추천 질문, 문서 필터, 기준일, 질문 입력창이 표시되고 인증 확인이 끝난다.
- [ ] 추천 질문: 첫 번째 추천 질문이 제출되고 답변 요약, 주장, 체크리스트, 원문 근거가 표시된다.
- [ ] 직접 질문: 버튼과 `Enter` 제출이 동작하고 `Shift+Enter`는 줄바꿈만 한다.
- [ ] AI 실행: `prepare → core → finalize`가 한 execution으로 완료되고 중간 요약이 최종 답변으로 교체된다.
- [ ] 근거 인용: 모든 핵심 주장에 인용이 있고 버튼이 해당 원문 카드를 열어 스크롤한다.
- [ ] 출처 링크: 법령명, 버전, 조문 위치, 인용문, 출처 링크가 보이고 외부 원문이 안전하게 열린다.
- [ ] 문서 필터: 법률, 시행령, 시행규칙, 행정규칙 필터가 원문 목록만 바꾸며 답변은 유지된다.
- [ ] 인용 필터 복원: 숨겨진 종류의 인용 버튼을 누르면 해당 문서 종류가 다시 선택된다.
- [ ] 기준일: 오늘 및 과거 기준일이 요청과 답변 메타데이터에 동일하게 반영된다.
- [ ] Markdown 내보내기: 체크리스트 파일이 내려받아지고 한글과 인용이 보존된다.
- [ ] CSV 내보내기: 체크리스트 파일이 내려받아지고 스프레드시트에서 열 수 있다.
- [ ] 익명 사용: 로그인 없이 질문할 수 있고 로그인 안내는 세션당 한 번만 표시된다.
- [ ] 익명 저장 경계: 로그인 후에도 이전 익명 질문은 저장되지 않고 다음 질문부터 기록된다.
- [ ] 로그인·가입: 모달 전환, 필수 동의, Google 인증, 사용자 표시가 정상 동작한다.
- [ ] 연속 질문: 후속 질문이 같은 대화 문맥과 기록에 저장된다.
- [ ] 새 질문: 실행 중이 아닌 상태에서 새 대화로 초기화되고 입력창에 포커스가 간다.
- [ ] 질문 기록: 새로고침 후 대화가 복원되고 질문, 답변, 기준일, 인용이 동일하다.
- [ ] 기록 페이지네이션: `더 보기`와 `이전 대화 불러오기`가 순서와 중복 없이 동작한다.
- [ ] 기록 삭제: 취소는 보존하고 확인은 해당 대화만 제거한다.
- [ ] PDF 내보내기: 로그인 후 저장된 질문에서 정상 다운로드된다.
- [ ] 로그아웃: 개인 기록과 계정 UI가 제거되고 익명 질문 기능은 유지된다.

## P1 입력·날짜·필터 경계

- [ ] 빈 값, 공백, 한 글자는 제출되지 않는다.
- [ ] 앞뒤 공백은 제거되고 실제 질문 내용은 유지된다.
- [ ] 한글 IME 조합 중 `Enter`가 질문을 제출하지 않는다.
- [ ] 2,000자는 입력할 수 있고 초과 입력은 제한된다.
- [ ] HTML 또는 스크립트 문자열은 실행되지 않고 텍스트로 표시된다.
- [ ] 빠른 연속 클릭이나 `Enter` 연타가 중복 실행을 만들지 않는다.
- [ ] 미래 날짜는 한국의 오늘 날짜를 넘지 못한다.
- [ ] KST 자정 전후 최대 날짜가 다음 한국 날짜로 갱신된다.
- [ ] 오래된 기준일에 자료가 없으면 설명 가능한 빈 결과가 표시된다.
- [ ] 문서 필터는 최소 한 종류를 유지한다.
- [ ] 선택 필터의 원문이 0건이어도 답변과 레이아웃이 유지된다.

## P1 검색·답변 경계

- [ ] 결과 없음은 `검색 결과가 없습니다`, 원인, 재검색 안내를 표시한다.
- [ ] `질문 구체화하기`는 입력창에 포커스하고 기존 질문을 선택한다.
- [ ] 법령명 없는 조문 질문은 내부 오류 대신 구체화 안내를 표시한다.
- [ ] 서비스 범위 밖 질문은 근거 없는 법률 답변을 생성하지 않는다.
- [ ] 존재하지 않는 인용 ID나 이동 불가능한 인용 버튼이 없다.
- [ ] `generation_error`는 제한된 횟수만 재시도하고 무한 로딩하지 않는다.
- [ ] `grounding_failed`와 `no_evidence`는 모델 기억으로 답을 보충하지 않는다.
- [ ] 한 번 실패한 다음 질문에서 AI 답변을 다시 시도할 수 있다.

## P1 네트워크·실행 상태 경계

- [ ] 연결 해제 시 오류가 표시되고 입력창이 복구되며 재연결 후 다시 질문할 수 있다.
- [ ] `502`, `503`, `504`는 제한된 횟수만 재시도하며 execution을 중복 생성하지 않는다.
- [ ] `400`, `401`, `402`, `409`, `429`는 자동 재시도하지 않고 설명 가능한 오류를 표시한다.
- [ ] `500`은 무한 재시도, 빈 화면, 스택 트레이스 또는 인증정보 노출 없이 종료된다.
- [ ] 일시적인 스트림 중단은 동일 execution에 제한적으로 재연결한다.
- [ ] 재연결 후 답변 문장이 중복되거나 이전 응답과 섞이지 않는다.
- [ ] 응답 중지는 취소 상태를 표시하고 늦게 온 응답이 화면을 덮어쓰지 않는다.
- [ ] 생성 중 `새 질문`은 이전 실행을 취소하고 새 대화를 연다.
- [ ] 생성 중 다른 기록 열기는 이전 실행의 늦은 응답을 무시한다.
- [ ] 생성 중 새로고침해도 영구 로딩 상태가 남지 않는다.
- [ ] 원문 0건, 1건, 다수 및 긴 법령명·인용문에서도 레이아웃이 깨지지 않는다.

## P1 인증·이력·내보내기 경계

- [ ] Google 인증 취소 또는 만료가 재시도 가능한 안내를 표시한다.
- [ ] OAuth 이동 경로는 내부 상대 경로만 허용한다.
- [ ] 세션 만료 후 개인 API는 로그인 필요 상태로 전환된다.
- [ ] 다른 탭에서 로그아웃하면 현재 탭의 개인 데이터도 제거된다.
- [ ] 기록 API 실패 시 기존 화면은 유지되고 오류만 표시된다.
- [ ] 같은 대화를 빠르게 반복해서 열어도 순서가 뒤집히거나 중복되지 않는다.
- [ ] 계정 삭제 취소는 데이터를 보존하고, 전용 테스트 계정의 확인 삭제는 데이터를 제거한다.
- [ ] 체크리스트가 없으면 내보내기 UI가 나타나지 않는다.
- [ ] 익명 PDF 요청은 로그인 필요 안내로 끝나고 `500`을 만들지 않는다.
- [ ] 쉼표, 따옴표, 줄바꿈이 있는 CSV 값이 올바르게 이스케이프된다.
- [ ] 다운로드 실패 후 버튼이 계속 `생성 중`으로 남지 않는다.

## P1 모바일·키보드·접근성 경계

- [ ] 375px와 430px에서 메뉴 열기, 닫기, 기록 선택이 가능하다.
- [ ] 1280px와 모바일에서 긴 답변이 가로 넘침이나 주요 조작 가림을 만들지 않는다.
- [ ] 모달의 `Tab`과 `Shift+Tab` 포커스가 내부에서 순환한다.
- [ ] `Escape`로 모달을 닫으면 포커스가 원래 제어로 돌아간다.
- [ ] 키보드만으로 질문, 필터, 인용, 내보내기, 로그인 조작이 가능하다.
- [ ] 로딩, 빈 결과, 오류 상태가 live region을 통해 전달된다.

## 완료 판정

모든 체크박스가 최신 증거와 함께 통과해야 완료다. 제품 결함이 발견되면 실패를 재현하는 자동화 테스트를
먼저 추가하고, 최소 수정 후 해당 항목과 전체 회귀를 다시 실행한다. 외부 서비스 장애나 실제 사용자 인증처럼
통제할 수 없는 조건은 조사 증거와 재개 조건을 기록하며, 임의로 통과 처리하지 않는다.
