# 실행 계획 0018: 실험 C — 지정 장·조 로컬 벡터 검색

상태: 완료
작성일: 2026-07-23
소유자: 주 에이전트

## 목적과 사용자 결과

세 법령을 기존 Open API client와 파서로 수집·정규화한다. 저작권법 제1장·제5장, 전기사업법
제1장·제6장, 신재생에너지법 제1조~제5조에 속한 기존 청크만 기존 NVIDIA NIM 임베더로 저장한다.
질문을 입력하면 제한된 로컬 corpus의 코사인 유사도 상위 3개와 점수를 터미널에 출력한다.

## 입력과 선택 계약

- 저작권법과 신재생에너지법은 prepare 시점의 현행 버전을 사용한다.
- 전기사업법은 과거 MST `180380`, 시행 2016-07-28 버전으로 고정한다.
- 제N장은 해당 표제가 붙은 첫 조부터 다음 장 표제 직전까지다.
- `제5장의2` 같은 가지 장은 `제5장`에 포함하지 않는다.
- 제1조~제5조에는 해당 숫자 범위의 가지조문과 모든 조·항·호·목 청크를 포함한다.
- 파서가 만든 청크의 내용·경계·순서는 바꾸지 않는다.
- corpus는 로컬 `.data`에만 저장하고 production DB와 Supabase를 변경하지 않는다.

## 범위와 비범위

범위:

- 기존 `LawOpenApiClient.document()`와 JSON 우선/XML 폴백 파서 재사용
- 지정 장·조의 시작·종료 경계 검증과 모든 하위 청크 선택
- 기존 `NvidiaNimEmbedder`의 passage/query 설정 재사용
- 로컬 JSON 원자 교체, exhaustive cosine top 3, 정상·실패·경계 테스트
- 실행 안내와 학습 문서 갱신

비범위:

- 파서 또는 청킹 규칙 변경
- HTML/PDF 크롤링
- production corpus·DB·검색 동작 변경
- 범위 밖 법률 검색 품질 보장
- 실험 B 사용자의 미커밋 결과 변경

## 완료 조건

- 준비 명령이 지정 범위와 모든 하위 청크만 저장한다.
- 지정 장·조 하나라도 없으면 embedding 전에 실패한다.
- corpus metadata에 선택 범위와 실제 조 경로·청크 수를 기록한다.
- 모든 passage vector는 기존 2048 검증→앞 512개→L2 재정규화 계약을 따른다.
- 새 corpus 완성 후에만 기존 2,006개 로컬 파일을 교체한다.
- 질문은 query embedding으로 만들고 저장 청크 전체의 cosine top 3만 출력한다.
- 테스트, Ruff, 문서 검사와 전체 검증이 통과한다.

## 잔여 한계

- 이 corpus는 사용자가 지정한 일부 구조만 포함하므로 전체 법률 검색 품질을 평가할 수 없다.
- 장 표제는 별도 도메인 필드가 아니라 각 장 첫 조의 본문 접두어에서 판정한다. 원문 형식이 바뀌어
  표제를 찾지 못하면 자동 추측하지 않고 실패한다.
- 로컬 corpus는 다른 PC에 자동 복제되지 않는다.

청크 205개와 passage embedding만 남아 있다. production DB와 기존 미커밋 실험 B 결과는 변경하지
않았다.
