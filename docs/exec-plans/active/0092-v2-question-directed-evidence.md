# V2가 질문에 필요한 구체 근거를 찾아 답하도록 개선

## 범위와 판단

[B-017](../completed/0088-answer-readability-and-evidence-layout.md)은 답변을 읽고 근거를 열어보는 흐름을 개선했다. 이번 문제는 질문이 요구하는 정보를 찾았는지에 있다. 필요한 근거가 검색되지 않았는지, 검색됐지만 답변에 빠졌는지부터 판별해야 하므로 별도 작업 B-020으로 등록한다. [B-019](0091-v2-cited-claim-consistency.md)는 이미 연결한 인용의 적용 대상·수치 일치를 맡는다.

- **전기사업 허가 신청 서류** — 신청서와 “해당 서류”라는 포괄 표현은 미달이다. 적용되는 항·호·별표 등 허용 코퍼스의 원문을 확인해 실제 신청서명과 제출 서류를 구체적으로 답한다. 관할은 서류 답변을 대신할 수 없다.
- **전기저장시설 설치 화재안전 기준** — 상위 법률을 언급하고 설치 수치 하나를 나열하면 미달이다. 질문에 직접 적용되는 기준의 정식 명칭과 해당 조항을 확인하고 무엇을 요구하는지 쉽게 설명한다. 질문만으로 적용 범위를 좁힐 수 없으면 확인된 범위와 필요한 추가 사실을 밝힌다.

위 두 건은 사용자가 지적한 실패 표본이다. 최종 법률 답안은 허용된 원문과 기준일을 대조한 후 확정한다.

## 실행 순서

1. **6건 수집과 판정 그룹 고정.** 결과는 서로 다른 실제 웹 V2 질문과 응답 6건이다. 위 두 질문과 비슷한 실패를 드러낼 수 있는 서로 다른 질문 4개를 고르고, 사용자 판정 3건에 위 두 건을 포함한다. 코드 버전, 기준일, 질문, 답변, 인용, 확인 가능한 검색 근거를 기록한다. 생성 실패는 별도 기록하고 답변 6건을 채운다. 대상은 `apps/api/evaluation/b020/raw/` 새 회차 JSON 약 80~200줄과 `apps/api/evaluation/b020/rounds/` 새 회차 JSON 약 30~60줄이다. 완료 증거는 6건의 출처와 3+3 배정이며, 각 JSON을 `python -m json.tool <경로>`로 검사한다. 의존성 없음.
2. **사용자 3건 판정.** 첫 3건의 실제 답변과 확인 가능한 근거를 사용자에게 보여주고, 기대 답변에 꼭 필요한 항목·근거와 허용할 불확실성을 직접 판정받는다. 대상은 해당 회차 JSON 약 20~45줄 추가다. 완료 증거는 세 사례 각각의 사용자 판정과 판정 이유다. 의존성은 1의 수집 회차다.
3. **Codex 3건 판정과 사용자 확인.** 사용자 판정에서 확인한 기준을 나머지 3건에 적용한다. 각 사례의 기대 답변, 필요한 근거, 실제 누락, 판단 이유를 작성해 사용자가 검토할 수 있게 제시한다. 대상은 해당 회차 JSON 약 20~45줄 추가다. 사용자가 Codex 판정을 적절하다고 확인하면 통과한다. 동의하지 않으면 이견을 기록하고 새 회차에서 1~3을 반복한다. 승인된 회차와 기각된 회차는 출처와 함께 남긴다. 완료 증거는 승인된 6건 판정이며 `python -m json.tool <회차 경로>`와 `git diff --check`를 실행한다. 의존성은 2의 사용자 판정이다.
4. **원인과 최소 수정 범위 확정.** 승인된 표본의 필요 근거가 코퍼스에 있는지, 검색 결과에 들어왔는지, 생성기에 전달됐는지, 최종 답변에 쓰였는지 차례로 대조한다. 검색 누락과 생성 누락이 서로 다른 원인이면 각각 독립적으로 검증할 수 있게 나눈다. 대상은 이 계획의 원인·수정 표 약 20~45줄과 승인 회차다. 완료 증거는 사례별 실패 지점, 수정 파일·현재 줄 범위, 예상 변경량, 정확한 회귀 명령과 기대 결과다. 의존성은 3의 승인이다.
5. **최소 수정과 재판정.** 4에서 확정한 회귀 사례가 기존 코드에서 실패함을 확인하고 원인이 있는 경로를 최소 수정한다. 정한 회귀 명령과 `git diff --check`를 실행한 뒤 같은 6개 질문을 웹 V2로 다시 실행한다. 정식 신청서와 서류, 구체 기준명과 적용 조항처럼 승인 판정에서 요구한 정보가 근거와 함께 들어왔는지 비교한다. 출처가 부족한 경우에는 확정할 수 없는 범위를 명시해야 한다. 대상은 4에서 확정한 코드·테스트와 새 비교 회차 JSON 약 40~80줄이다. 완료 증거는 승인된 6건의 기준 충족, 근거 없는 추가 주장 없음, 회귀 통과, 비교 기록과 로컬 커밋이다. 미달 사례는 4~5로 돌린다.

## 1회차 근거 전달 경로 확인

## 1회차 원인과 구현 작업

개발 DB 읽기 전용 조회에서 전기사업법 시행규칙 제4조 제1항 제1~12호는 현재 활성 색인에 있었다. 제4조의 제출서류가 빠진 사례는 이미 색인된 자료를 검색에서 가져오지 못한 것이다. 같은 문서의 별지 경로와 전기안전관리법 시행규칙 및 건축물 피난·방화구조 규칙의 정확한 제목으로 조회한 조항은 반환되지 않았다. 별지와 규칙의 공식 원자료 수록 여부는 별도 확인 대상으로 둔다.

1. **검색 근거가 있는 질문의 요약 계약.** 결과는 V2 첫 요약이 근거에 있는 정식 기준명과 구체 서류를 우선 쓰고, 확인할 행동을 요약에도 담되 상세 체크리스트를 유지하며, 생략한 관련 내용이 어느 원문에 있는지 안내하는 것이다. 대상은 `apps/api/app/adapters/openai_answerer.py` L218-L232 약 5~9줄, `apps/api/app/domain/generation_profiles.py` L48 1줄, `apps/api/tests/test_layperson_prompt_v2.py` L244-L250 약 6~10줄, `apps/api/tests/test_generation_profiles.py` L42 1줄이다. 최종화가 검증된 core 요약을 유지하므로 core 지침에 기대 동작을 넣는다. 존재하지 않는 인용이나 서류를 추정하지 않으며 요약과 상세 체크리스트의 구조를 유지한다. 순서는 core 프롬프트 회귀 실패, 최소 수정, `cd apps/api; ..\..\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider tests/test_layperson_prompt_v2.py tests/test_generation_profiles.py tests/test_answer_quality_contract.py tests/test_v2_question_executions.py`, `git diff --check`다. 완료 증거는 해당 회귀와 기존 검증 통과 및 2·3번 질문의 실제 V2 재실행 결과다.
2. **색인된 첨부서류 검색의 별도 검증.** 검색 결과에 부모 항과 일부 호만 들어올 때 같은 문서 버전의 직접 하위 호를 모을 수 있는지 현재 검색 계약을 조사한다. 원인 확인 후 허가 서류의 호를 가져오는 실패 회귀, 최대 근거 수, 출처 추적과 다른 문서 혼입 방지 기준을 이 문서에 별도 확정한다. 별지 원문과 부령의 추가 수집 여부는 현재 코퍼스와 공식 원자료를 대조한 후 결정한다.
