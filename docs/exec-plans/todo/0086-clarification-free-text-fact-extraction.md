# Clarification 자유 문장 fact 추출

## 배경과 목표

Web은 사용자가 입력한 자유 문장을 다음 clarification 요청으로 보낸다. 현재 extractor는 구조화된 JSON만 `submitted_facts`로 읽으며, 일반 문장은 의도만 분류한다. 이로 인해 사용자가 필요한 사실을 답해도 case의 fact가 미답변으로 남을 수 있다.

사용자 답변에서 저장된 미해결 fact의 식별자에 대응하는 사실을 추출·검증·병합하고, 일부만 답한 경우 답하지 않은 항목만 다시 묻는 흐름을 만든다.

## 범위와 안전 계약

- 최초 질문 판정과 후속 턴 추출의 책임을 분리한다. 추출기는 소유권·만료를 확인해 조회된 case의 미해결 fact만 대상으로 한다.
- 자유 문장, 여러 fact의 한꺼번에 답변, 일부 답변, 모호한 답변, 답변 거부, `지금 정보로 답변`, 취소·새 질문 의도를 구분한다. 불확실한 값은 임의로 채우지 않는다.
- JSON 구조화 입력의 기존 계약을 보존한다. 모델 또는 규칙 기반 추출 방식을 선택할 때 비용·지연·실패 시 중립 결과·개인정보 경계를 먼저 결정한다.
- 사용자 원문·fact 값·capability를 이벤트와 로그에 싣지 않고, 알려진 fact ID 이외의 제출은 병합하지 않는다.

## 완료 조건

- 실제 Web 형식의 자유 문장으로 답한 fact가 저장되고 `remaining_count`가 감소한다.
- 부분·복수·모호·거부·취소·새 질문·추출 실패 경계가 정상·실패·경계 테스트로 고정된다.
- B-016이 저장된 사실을 사용할 수 있도록 case의 값·상태 계약을 유지한다.
