# 0043: 일반인 답변 계약 v2와 가독성 평가

상태: `제안됨 · 미착수`

제안 출처: 2026-08-09 사용자가 실제 태양광 사업 질문의 AI 답변을 검토한 뒤, 법률을 처음 접하는
사람도 바로 이해할 수 있도록 답변 생성 가이드를 주는 개선안 중 **B안(일반인 답변 계약 v2 +
평가 기준)**을 다음 작업으로 선택했다.

## 목적

현재 인용·근거 부족·구조 검증 계약은 유지하면서, AI 답변을 법률 조사 보고서 문체가 아니라 처음
보는 사용자가 "무엇을 확인하고 다음에 무엇을 해야 하는지" 바로 이해할 수 있는 안내문 문체로
생성한다. 저장소의 [제품 디자인 원칙](../../DESIGN.md)에 있는 "전문 용어에는 원문 용어를
보존하면서 쉬운 설명을 제공한다"를 프롬프트와 검증 가능한 평가 기준에 실제로 연결한다.

## 현재 확인된 문제

- 현재 system prompt는 제공된 근거만 사용하고 인용을 붙이는 안전 규칙은 상세하지만, 독자 수준,
  전문용어 설명 방식, 정보 우선순위와 문장 길이는 정하지 않는다.
- `summary`·`sections`·`checklist`·`limitations` 구조가 그대로 화면에 노출되므로, 모델이 법령명,
  조문 번호와 법률 용어를 반복하면 사용자는 핵심 행동보다 전문적인 조사 문체를 먼저 보게 된다.
- 현재 테스트는 스키마·인용 ID·금지된 과장 주장·fallback을 확인하지만, 처음 보는 사용자의 이해
  가능성은 측정하지 않는다.
- 검색 근거가 질문의 핵심 facet을 놓친 문제는 생성 문체로 감추지 않는다. 근거 순위 개선은
  [0042](0042-wire-reranking-into-live-search-path.md)의 별도 책임으로 유지한다.

## 범위

### 1. 필드별 일반인 답변 계약 v2

- `summary`: 최대 3문장 안에서 현재 근거로 확인되는 결론과 가장 먼저 할 일을 말한다.
- `sections[].claim`: 사용자의 질문에 직접 답하는 쉬운 소제목 또는 행동 문장으로 쓴다.
- `sections[].explanation`: 전문용어는 쉬운 뜻을 먼저 설명하고 원문 용어를 괄호 안에 한 번만
  보존한다. 한 문장에는 하나의 조건·예외·행동만 담는다.
- `checklist[].label`: 사용자가 확인하거나 준비할 정보를 동사형 행동으로 쓴다.
- `limitations`: 중요한 한계만 최대 3개로 제한하고, "현재 확인된 것"과 "아직 확정할 수 없는 것"을
  분리한다.
- 법률명·조문 번호는 이해에 꼭 필요한 경우를 제외하고 본문에서 반복하지 않으며, 실질 주장은
  기존 citation ID로 연결한다.
- 제공된 근거에 없는 일반 절차·기관·법률을 쉬운 설명이라는 이유로 추가하지 않는다.

### 2. 새 생성 프로필

- 기존 `answer-system-prompt-v1`과 그 SHA를 덮어쓰지 않는다.
- prompt/profile version을 v2로 올려 답변 이력과 평가 artifact에서 v1·v2를 구분한다.
- 기존 `DraftAnswer` 스키마와 인용 검증 계약은 우선 유지한다. 스키마 변경은 v2 출력만으로 목표를
  달성하지 못했을 때 별도 승인한다.

### 3. 가독성 평가 계약

결정적 테스트는 프롬프트에 아래 규칙이 실제 포함됐는지 검사하고, 실제 모델 출력은 다음 rubric으로
사람이 비교한다.

1. 첫 문단만 읽어도 질문에 대한 현재 결론과 다음 행동을 알 수 있다.
2. 처음 등장하는 법률 전문용어의 쉬운 뜻을 같은 위치에서 알 수 있다.
3. 한 문장에 여러 조건·예외·기관을 몰아넣지 않는다.
4. 체크리스트만 읽어도 사용자가 준비할 정보를 알 수 있다.
5. 한계가 핵심 근거보다 먼저 나오거나, 같은 한계를 표현만 바꿔 반복하지 않는다.
6. 쉬운 설명을 위해 근거 없는 법률 주장이나 일반 태양광 사업 절차를 추가하지 않는다.

### 4. 제한된 실제 비교

- D-10 첫 질문 `lay-energy-0201`을 필수 사례로 사용한다.
- `partially_answerable` 외에 `fully_answerable` 또는 `clarification_required` 대표 사례를 포함해
  총 3문항 이내에서 v1·v2를 비교한다.
- 실제 NVIDIA 호출 횟수와 재시도 상한은 실행 전에 다시 명시하고 사용자의 외부 호출 승인을 받는다.
- hosted 비교 전에 Web 질문 경로가 59초마다 새 request ID로 최대 3회 재요청하는 계약과, API가
  Vercel 강제 종료 전에 AI 답변 또는 안전한 검색 전용 fallback을 반환하는지 확인한다.

## 비범위

- 답변 화면의 점진적 공개, 섹션 접기, API 응답 스키마 재설계
- 검색·재순위·문맥 조립 변경 또는 근거 부족을 프롬프트로 보완
- 인용 검증 완화, 법률 기억 기반 보충, 다른 corpus·외부 웹 근거 도입
- 일반 가독성 위반을 즉시 Production fallback 사유로 만드는 runtime style gate
- Vercel 함수 시간 제한과 Web 재요청 자체의 구현 변경; 이는 먼저 현행 계약을 별도로 진단한다.

## 의존성

- D-10 동결 질문·근거와 answerability 판정
- 현재 `DraftAnswer`·`QuestionResponse`·citation 구조
- 실제 비교 시 정상 동작하는 Production 또는 동등한 hosted 질문 경로
- [0042](0042-wire-reranking-into-live-search-path.md)는 독립 작업이며 이 항목의 선행 조건이 아니다.
  다만 v2 평가에서 핵심 근거 누락이 발견되면 문체 실패와 검색 실패를 분리해 0042에 기록한다.

## 승격 조건

- 사용자가 이 항목의 착수를 명시한다.
- 착수 시 실제 비교 문항 3개, NVIDIA 호출 상한, 일반인 rubric의 합격 기준을 확정한다.
- 실행 계획을 작성하면 저장소 규칙에 따라 같은 번호의 이 파일을 `active/`로 이동한다.

## 완료 조건

- 일반인 답변 계약 v2가 prompt와 새 generation profile version으로 구현된다.
- prompt·schema·인용·fallback 관련 결정적 테스트가 통과한다.
- `lay-energy-0201`을 포함한 최대 3문항 v1·v2 비교 결과에 raw structured response, profile SHA,
  latency, route, action, citation과 rubric 판정을 남긴다.
- 중대 인용·기준일·규범 오류는 0건이고, 근거 부족은 쉬운 문체로 숨기지 않는다.
- 사용자 검토에서 v2가 첫 문단 이해, 전문용어 설명, 다음 행동, 한계 구분 rubric을 충족한다.
- 중요한 결정과 실제 결과를 관련 설계 문서의 결정 기록에 반영한다.
