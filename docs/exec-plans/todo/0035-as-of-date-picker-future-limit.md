# 0035: 기준일 선택 범위를 오늘까지로 제한

상태: `제안됨 · 미착수`

제안 출처: 2026-08-08 사용자가 웹 UI의 기준일(법령 as_of_date) 날짜 선택기에서 미래 날짜를
고를 수 있는 걸 지적하고, 오늘까지만 선택 가능하도록 바꿔야 한다고 지시했다.

## 원인

`apps/web/app/page.tsx`의 기준일 입력이 `max` 제약 없이 렌더링된다:

```jsx
<input aria-label="법령 기준일" onChange={(event) => setAsOf(event.target.value)} type="date" value={asOf} />
```

(현재 [page.tsx:784](../../../apps/web/app/page.tsx:784) 부근)

`asOf`의 초기값은 `new Date().toISOString().slice(0, 10)`([page.tsx:274](../../../apps/web/app/page.tsx:274))로 오늘이지만, 사용자가 달력에서 임의로 미래 날짜를 골라도 막는 로직이 없다.

## 설계 (미착수, 방향만)

- `<input type="date">`에 `max={오늘 날짜(YYYY-MM-DD)}`를 추가한다. 오늘 날짜는 이미
  `asOf` 초기값 계산에 쓰는 것과 같은 방식(`new Date().toISOString().slice(0, 10)`)으로
  구할 수 있다.
- 타임존: `toISOString()`은 UTC 기준이라 KST 자정 근처에 하루 어긋날 수 있다 - 서버의
  `as_of_date` 검증(`_require_supported_as_of_date`)이 어떤 기준으로 "오늘"을 판단하는지
  먼저 확인하고 프론트 `max`도 같은 기준에 맞춘다.
- 브라우저 네이티브 `max` 속성은 일부 브라우저에서 값을 벗어난 직접 타이핑까지는 못 막을
  수 있으니, 필요하면 `onChange`에서도 클램프한다.

## 비범위

- 과거 날짜 선택 하한(법령 코퍼스 최초 수집일 이전 등)을 막는 것은 이번 항목이 아니다 -
  별도 결정이 필요하면 새 항목으로 등록한다.

## 승격 조건

- 사용자가 착수를 명시한다.

## 완료 조건

- 기준일 달력에서 오늘 이후 날짜를 선택할 수 없다(키보드 직접 입력 포함).
- 오늘 날짜는 여전히 선택 가능하다.
- 회귀 테스트 추가(달력 `max` 값 계산 로직이 순수 함수로 분리 가능하면 유닛 테스트로).
