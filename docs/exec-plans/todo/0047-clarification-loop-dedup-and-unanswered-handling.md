# 0047: 추가 정보 재질문 루프 중복 제거 및 미답변 처리

상태: `제안됨 (2026-08-10), 2026-08-18 갱신 — v2 아키텍처(LangGraph 기반 재작성)로 전환하며
같은 문제를 LangGraph의 상태 그래프·조건부 엣지로 해결할 예정이라 별도 즉시 착수 대상이
아니다. v2 전환 전까지는 이 문서에 기록된 재현 로그·완료 조건을 v2 clarification 루프
설계의 입력으로 유지한다.`

제안 출처: 사용자가 `/v1/questions`에서 재현된 실제 fetch 로그(동일 대화, `answer_mode=terra`)를
근거로 무한루프 버그를 보고하고 TODO 등록을 지시했다. 재현 로그에서 사용자가 추가 정보를
채워 재전송할 때마다 `clarification_required` 응답이 이전에 이미 채운 항목까지 포함해 다시
질문 목록에 얹었고, 매 라운드 질문 텍스트가 이전 라운드 전체를 그대로 누적·중첩해 메시지가
계속 길어지며 끝나지 않았다.

## 목표

- 후속 `clarification_required` 응답이 직전 라운드에서 이미 답변된 항목(빈 값이 아닌 값이
  채워진 필드)을 다시 질문 목록에 포함하지 않게 한다.
- 사용자가 특정 추가 질문에 값을 채우지 않았거나(`모름`, 빈 문자열, `정해주는대로` 등) 명백히
  회피성 응답을 반복한 경우, 같은 항목으로 무한정 재질문하지 않고 해당 필드를 "답변하지 않음"
  상태로 확정해 라우팅을 다음 단계로 진행시킨다.
- 재질문 라운드 수 또는 누적 메시지 길이에 대한 상한을 두어, 위 두 조건이 실패하더라도 루프가
  물리적으로 종료되게 한다.

## 포함 범위

- `apps/api/app/domain/routing.py`, `apps/api/app/domain/answer_actions.py`,
  `apps/api/app/application/answering.py` 등 `clarification_required` 생성·후속 처리 경로에서
  이전 대화 턴(`conversation_context`)의 응답 값을 파싱해 이미 채워진 필드를 다음 질문 목록에서
  제외하는 로직 설계
- "답변하지 않음"으로 간주할 값의 판정 기준(빈 값, 사용자가 재차 회피한 값 등)과 그 이후 라우팅
  동작(검색 진행 또는 명시적 한계 고지) 설계
- 재질문 라운드 상한 또는 동등한 안전장치 설계와 상한 도달 시 사용자에게 보여줄 응답 계약
- 관련 정상·회귀 테스트(`apps/api/tests/test_routing.py`,
  `apps/api/tests/test_routing_pipeline.py`, `apps/api/tests/test_answer_actions.py` 등) 추가

## 비범위

- 추가 정보 질문 문항 자체의 문구·항목 구성 변경(현재 항목 구성이 적절한지는 별도 판단)
- `clarification_required` 이외의 라우팅 액션 변경
- 프론트엔드(Web) UI에서 추가 정보 입력 폼을 구조화된 필드로 바꾸는 변경(현재는 자유 텍스트
  복사-붙여넣기 방식이며, 이번 TODO는 서버 측 중복 제거·종료 조건에 한정)

## 완료 조건

- 동일한 항목에 이미 값을 채워 재전송하면 다음 `clarification_required` 응답이 해당 항목을
  다시 질문하지 않는다.
- 사용자가 특정 항목에 반복해서 답변하지 않으면(설계에서 정한 기준 충족 시) 해당 항목이
  "답변하지 않음"으로 확정되고 라우팅이 멈추지 않고 진행된다.
- 재질문이 상한에 도달하면 무한히 누적되지 않고 정해진 방식으로 종료된다.
- 재현 로그와 동등한 시나리오(항목 일부만 채움 → 재전송 → 재질문)에 대한 회귀 테스트가 통과한다.

## 승격 조건

- "답변하지 않음"으로 판정하는 구체적 기준(예: 몇 라운드 반복 후 확정할지, `모름`/빈 값을 즉시
  확정할지)을 사용자가 결정한다.
- 재질문 라운드 상한 도달 시 사용자에게 보여줄 문구·후속 액션(검색 진행 vs 한계 고지)을 사용자가
  승인한다.
