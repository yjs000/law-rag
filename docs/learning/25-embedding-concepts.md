# 임베딩의 전체 개념: 차원, 내적, 코사인 유사도와 축약

## 먼저 한 문장으로

임베딩은 문장 같은 대상을 숫자 벡터로 바꾸고, 코사인 유사도는 두 벡터가 얼마나 비슷한 방향을
가리키는지 측정한다. NVIDIA Nemotron 3 Embed 1B의 2048차원 출력을 512차원으로 줄일 때는 모델
카드가 허용한 **앞 512개 좌표만 남긴 뒤 L2 재정규화**한다. 이 과정은 원래 2048차원 방향이나
삭제된 정보를 보존하지 않는다. 남은 512차원 안의 방향만 그대로 두고 벡터 길이를 다시 1로 만든다.

## 1. 임베딩이란 무엇인가

임베딩(embedding)은 텍스트를 여러 실수로 이루어진 벡터로 바꾸는 모델의 출력이다.

```text
"전기사업자는 허가를 받아야 한다"
    -> embedding model
    -> [0.013, -0.072, 0.118, ...]
```

모델은 학습 과정에서 관련 있는 텍스트가 표현 공간에서 가까워지도록 숫자 배치를 익힌다. 그래서
검색할 때 질문과 문서를 같은 모델로 임베딩하고 벡터의 유사도를 비교할 수 있다. 다만 각 좌표를
사람이 읽어 “첫 번째 값은 허가, 두 번째 값은 사업”처럼 해석하는 것은 보통 불가능하다. 의미는 한
좌표가 아니라 전체 좌표의 관계에 분산되어 있다.

임베딩은 원문이나 정답이 아니다. 숫자, 부정어, 예외 규정처럼 법적으로 중요한 차이를 놓칠 수 있고,
높은 유사도도 두 문장의 법적 의미가 같다는 증명이 아니다.

## 2. 벡터와 차원

벡터(vector)는 순서가 있는 숫자 목록이다. 원점에서 한 점까지 그은 화살표로 생각해도 된다.

```text
[3, 4]                    2차원 벡터
[0.2, -0.7, 0.1]         3차원 벡터
[x1, x2, ..., x2048]     2048차원 벡터
```

차원(dimension)은 숫자의 개수이자 표현 공간의 축 개수다. 2048차원은 숫자가 2048개라는 뜻이지,
문장에 뜻이 2048개 있거나 단어가 2048개라는 뜻이 아니다. 사람은 2048차원 공간을 눈으로 그릴 수
없지만, 덧셈·길이·각도 계산은 2차원과 같은 공식으로 할 수 있다.

서로 다른 모델의 512차원 벡터 두 개는 길이가 같아도 바로 비교할 수 없다. 각 모델이 학습한 좌표계가
서로 다르기 때문이다. 같은 모델에서도 질문은 `query`, 검색 대상 문서는 `passage`처럼 모델이 정한
입력 계약을 동일하게 지켜야 한다.

## 3. norm은 벡터의 길이

norm(노름)은 벡터의 크기를 재는 규칙이다. 임베딩에서 흔히 말하는 L2 norm은 원점부터 벡터 끝점까지의
직선거리다. 피타고라스 정리를 모든 차원으로 확장한 것이다.

```text
||v||₂ = sqrt(v1² + v2² + ... + vn²)
```

예를 들어 `v=[3, 4]`이면 다음과 같다.

```text
||v||₂ = sqrt(3² + 4²) = 5
```

`norm=1`인 벡터를 단위 벡터(unit vector)라고 한다. `norm=0`인 영벡터는 방향이 없으므로 코사인
유사도를 계산할 수 없다.

## 4. 정규화와 재정규화

L2 정규화(normalization)는 벡터의 모든 좌표를 그 벡터의 L2 norm으로 나누는 연산이다.

```text
v = [3, 4]
||v||₂ = 5
normalize(v) = [3/5, 4/5] = [0.6, 0.8]
```

새 벡터의 길이는 `sqrt(0.6² + 0.8²) = 1`이다. 모든 좌표에 똑같은 양수 `1/5`를 곱했기 때문에
좌표 사이의 비율 `3:4`와 화살표 방향은 그대로이고 길이만 줄어든다. “1보다 작아진 길이를 1로
만든다”는 것도 같은 원리다. 예를 들어 norm이 `0.5`라면 모든 좌표를 `0.5`로 나누므로 2배가 되고,
방향은 그대로인 채 길이만 1이 된다.

재정규화(renormalization)는 이미 정규화됐던 벡터를 자르는 등 변형한 뒤 다시 정규화한다는 뜻이다.
새로운 별도 수학 연산이 아니라 “한 번 더 정규화”하는 것이다.

## 5. 내적은 같은 자리끼리 곱해 더한 값

두 벡터 `a`, `b`의 내적(dot product)은 같은 위치의 값을 곱해 모두 더한 값이다.

```text
a · b = a1*b1 + a2*b2 + ... + an*bn

[1, 2] · [3, 4] = 1*3 + 2*4 = 11
```

기하학적으로는 다음 관계가 있다.

```text
a · b = ||a||₂ * ||b||₂ * cos(theta)
```

`theta`는 두 화살표 사이의 각도다. 같은 방향의 성분은 양수로 더해지고, 반대 방향의 성분은 음수로
상쇄된다. 그러나 내적은 방향뿐 아니라 두 벡터의 길이에도 커진다. 같은 방향이라도 아주 긴 벡터의
내적이 더 크므로, 방향만 비교하려면 길이의 영향을 제거해야 한다.

## 6. 코사인과 코사인 유사도

코사인(cosine)은 직각삼각형에서 각도와 변의 비율을 연결하는 함수다. 벡터에서는 두 화살표 사이의
각도를 나타내는 값으로 쓴다.

```text
cosine_similarity(a, b) = (a · b) / (||a||₂ * ||b||₂)
```

내적을 두 벡터 길이의 곱으로 나누면 크기의 영향이 사라지고 방향만 비교된다.

- `1`: 같은 방향
- `0`: 직교, 즉 방향상 겹치는 성분이 없음
- `-1`: 정반대 방향

예를 들어 `a=[1, 0]`, `b=[1, 1]`이면 내적은 `1`, norm은 각각 `1`, `sqrt(2)`이므로 코사인
유사도는 약 `0.707`이다.

두 벡터가 모두 L2 정규화돼 norm이 1이면 분모가 1이므로 내적과 코사인 유사도가 같다.

```text
정규화된 a, b:  a · b = cosine_similarity(a, b)
```

이 성질 때문에 벡터 검색 시스템은 단위 벡터를 저장하고 빠른 내적 검색으로 코사인 순위를 구현할 수
있다. OpenAI도 자사 임베딩이 길이 1로 정규화되어 코사인과 유클리드 거리의 순위가 같고, 코사인을
내적으로 더 빠르게 계산할 수 있다고 설명한다.

코사인 유사도는 확률이 아니다. `0.9`가 90% 정답 또는 90% 같은 법률 효과를 뜻하지 않는다. 점수
분포와 유효한 임계값은 모델과 데이터에 따라 달라서 실제 관련·비관련 문장 평가셋으로 정해야 한다.

## 7. 왜 임베딩 검색에 코사인을 쓰는가

임베딩 모델은 텍스트의 관계가 벡터 공간의 상대적 위치와 방향에 드러나도록 학습된다. 코사인은 문장
길이 등에 따라 달라질 수 있는 벡터의 절대 크기보다 방향을 비교한다. 검색 흐름은 다음과 같다.

```text
질문 --같은 모델/query--> 질문 벡터
문서 --같은 모델/passage--> 문서 벡터들
질문 벡터와 각 문서 벡터의 cosine 계산
점수가 높은 문서부터 정렬
```

코사인이 언제나 최선이라는 뜻은 아니다. 모델 카드가 권장하는 similarity, 정규화 방법, query와
passage 설정을 먼저 따라야 한다. 키워드가 중요한 법률 검색에서는 임베딩 검색과 키워드 검색을 함께
쓰고 검색 결과를 별도 평가하는 편이 안전하다.

## 8. 2048차원을 앞 512개로 자르면 생기는 일

2048차원 벡터 `v`를 앞부분 `p` 512개와 뒷부분 `q` 1536개로 나누어 보자.

```text
v = [p, q]
||v||₂² = ||p||₂² + ||q||₂²
```

전체 벡터가 단위 벡터라면 `||v||₂=1`이다. `q`에 0이 아닌 값이 하나라도 있으면 `q`를 버린 뒤의
`||p||₂`는 1보다 작다. 그래서 다음과 같이 재정규화한다.

```text
u = p / ||p||₂
```

여기서 정확히 구분해야 할 방향이 두 가지다.

1. **원래 2048차원 방향은 유지되지 않는다.** 뒤의 1536개 좌표와 그 좌표가 담던 정보가 사라졌기
   때문이다. 2048차원 화살표와 512차원 화살표는 애초에 서로 다른 공간에 있다.
2. **남은 512차원 안에서 `p`의 방향은 재정규화해도 유지된다.** `p`의 모든 좌표에 같은 양수
   `1/||p||₂`를 곱하므로 좌표 간 비율이 바뀌지 않기 때문이다.

재정규화는 삭제된 1536개 값을 추측하거나 복원하지 않는다. 남은 화살표의 길이만 1로 맞춘다.

순수 코사인 공식은 계산할 때 어차피 norm으로 나누므로 같은 두 truncated vector를 비교하면
재정규화 전후 코사인 값은 수학적으로 같다. 그래도 재정규화하는 이유는 세 가지다.

- NVIDIA 모델 카드가 축약 후 similarity 계산 전에 L2 재정규화를 요구한다.
- 저장되는 모든 벡터가 `norm=1`이라는 계약을 유지할 수 있다.
- 코사인 대신 내적을 쓰는 검색 시스템에서도 같은 순위를 얻을 수 있다.

차원이 2048에서 512로 줄면 저장할 실수 개수와 단순 벡터 연산량은 약 4분의 1이 된다. 대신 삭제된
정보 때문에 유사도와 검색 순위가 바뀔 수 있다. “공식 지원”은 2048차원과 품질이 완전히 같다는 뜻이
아니므로 대표 질의 평가가 필요하다.

## 9. 왜 하필 앞 512개인가

일반 임베딩 벡터는 임의로 잘라 쓰면 안 된다. 마지막 512개나 무작위 512개가 유용하다는 보장이
없다. 이 모델은 NVIDIA 공식 모델 카드가 **첫 1024개 또는 첫 512개를 유지하는 축약**을 명시했기
때문에 prefix인 `vector[:512]`를 사용할 수 있다.

일반적으로는 Matryoshka Representation Learning처럼 짧은 앞부분도 독립적으로 유용하도록 표현을
학습하는 방법이 있다. 다만 이 논문은 “왜 prefix 축약이 가능한 모델이 존재하는가”를 설명하는 일반
예시다. NVIDIA 공개 모델 카드가 이 모델에 정확히 그 학습법을 썼다고 밝히지는 않았으므로, 해당
기법을 사용했다고 단정하지 않는다. 이 프로젝트의 판단 근거는 NVIDIA가 공개한 출력 계약이다.

## 10. 모델 카드와 API는 서로 다른 층이다

모델 카드(model card)는 모델의 목적, 입력과 출력, 평가 조건, 적합한 용도, 한계 등을 설명하는
문서다. Model Cards 논문은 모델의 사용 조건과 성능 특성을 함께 기록해 투명한 보고를 돕는 문서화
방식을 제안했다. 모델 카드는 API 그 자체가 아니라 모델을 올바르게 이해하기 위한 설명서에 가깝다.

API는 그 모델을 네트워크로 호출하는 서비스 인터페이스다. 같은 모델 개념이라도 배포 서버가 어떤
옵션을 구현했는지는 별도 문제다.

```text
모델의 표현 능력·출력 계약       -> 모델 카드
요청 필드·허용 값·오류 응답       -> API reference
프로젝트가 실제로 적용하는 변환   -> adapter와 테스트
```

일부 모델과 API는 `dimensions=512` 같은 옵션을 받아 서버 안에서 축약된 벡터를 반환한다. 예를 들어
OpenAI의 `text-embedding-3` 계열은 `dimensions` 매개변수로 기본 출력보다 짧은 임베딩을 요청할 수
있다. 반면 NVIDIA NIM의 옵션은 모델별로 지원 범위가 다르다.

현재 NVIDIA Embedding NIM API reference에 따르면 `nvidia/nemotron-3-embed-1b`는
`dimensions`를 생략하거나 `2048`만 허용한다. `dimensions=512` 또는 `1024` 요청은 HTTP 400과
함께 허용값이 2048뿐이라는 오류를 반환한다. 동시에 NVIDIA 모델 카드는 반환된 2048차원 중 첫
1024개 또는 512개를 유지할 수 있다고 설명한다. 따라서 둘은 다음처럼 함께 해석해야 한다.

```text
NIM 요청: dimensions를 보내지 않음
NIM 응답: 2048차원
클라이언트: 응답이 정확히 2048차원인지 검증
클라이언트: 앞 512개 선택
클라이언트: L2 재정규화
최종 출력: 기존 저장소 계약에 맞는 512차원 단위 벡터
```

즉 모델은 prefix 축약을 허용하지만, 현재 hosted API가 그것을 서버 측 옵션으로 대신 수행하지 않는
것이다. 어떤 서비스가 `dimensions`를 제공하고 다른 서비스가 제공하지 않는 이유는 모델 설계와
서빙 구현·버전의 지원 범위가 다르기 때문이다. 옵션 이름만 보고 추측하지 말고 해당 모델 카드와 API
reference를 함께 확인해야 한다.

## 11. 실험 B에서 확인할 것

실험 결과값을 미리 정답처럼 기록하지 않는다. 직접 실행한 뒤 다음만 확인한다.

1. NIM 원본 응답이 문장마다 정확히 2048차원인지
2. adapter 최종 벡터가 문장마다 정확히 512차원인지
3. 모든 값이 유한한 실수인지, NaN이나 Infinity가 없는지
4. 두 최종 벡터의 L2 norm이 부동소수점 오차 범위에서 1에 가까운지
5. 코사인 유사도가 `[-1, 1]` 범위인지
6. 같은 문장, 관련 문장, 무관한 문장을 바꿔 넣었을 때 상대적 순서가 상식적인지
7. 점수가 이상하면 model ID, `query`/`passage`, 앞 512개 slicing, 재정규화 순서가 같은지

한 문장 쌍의 점수만으로 검색 임계값을 정하면 안 된다. 실제 법률 질의와 관련·비관련 조문으로 평가셋을
만들어 순위 품질을 측정해야 한다.

실제 실행값은 예상 설명과 섞지 않고
[실험 B 실제 출력과 반복 실행 비교](../generated/experiment-b-embedding-results.md)에 보존한다. 같은
명령을 반복하면 표시된 cosine뿐 아니라 512개 좌표 전체의 정확 일치 여부와 최대 차이를 비교한다.

## 12. 자주 생기는 오해

| 오해 | 정확한 설명 |
| --- | --- |
| 2048차원은 의미가 2048개다 | 숫자 좌표가 2048개라는 뜻이며 개별 축은 보통 사람이 이름 붙일 수 없다. |
| 512개를 잘라도 원래 방향이 유지된다 | 원래 2048차원 방향은 사라진다. 남은 512차원 벡터를 정규화할 때 그 안의 방향만 유지된다. |
| 재정규화가 삭제된 정보를 복원한다 | 복원하지 않는다. 남은 좌표 전체를 같은 비율로 확대해 norm만 1로 만든다. |
| 내적과 코사인은 항상 같다 | 두 벡터가 단위 벡터일 때만 같다. 일반 내적은 벡터 길이의 영향도 받는다. |
| 코사인 0.9는 90% 같은 뜻이다 | 확률이 아니라 방향 유사도다. 법률적 동일성도 보장하지 않는다. |
| 모든 임베딩은 앞부분을 잘라도 된다 | 모델 문서가 prefix 축약을 명시할 때만 사용해야 한다. |
| API에 `dimensions` 필드가 있으면 512를 받을 수 있다 | 허용 차원은 모델별로 다르다. 이 NIM 모델은 현재 API에서 2048만 허용한다. |
