# 코사인 유사도와 임베딩 비교

## 결론

코사인 유사도는 두 임베딩 벡터가 원점에서 얼마나 같은 방향을 가리키는지 측정한다. 벡터의 절대
크기보다 방향을 비교하므로 문장 임베딩의 의미적 관련성을 비교할 때 널리 사용한다. 값은 보통
`-1`에서 `1` 사이지만 확률이나 법률적 동일성 점수가 아니다.

## 용어

- 임베딩: 텍스트의 특징을 여러 실수로 표현한 고차원 벡터
- 내적: 같은 위치의 두 값을 곱해 모두 더한 값
- L2 norm: 벡터 길이. 각 값을 제곱해 더한 뒤 제곱근을 취한다.
- 정규화: 벡터를 자기 L2 norm으로 나눠 길이를 1로 만드는 과정
- 코사인 유사도: 두 벡터의 내적을 두 norm의 곱으로 나눈 값

## 계산

두 벡터 `A`, `B`의 코사인 유사도는 다음과 같다.

```text
cosine_similarity(A, B) = dot(A, B) / (norm(A) * norm(B))
```

예를 들어 `A=[1, 0]`, `B=[1, 1]`이면 내적은 `1`, norm은 각각 `1`, `sqrt(2)`이므로 유사도는
약 `0.707`이다. 완전히 같은 방향은 `1`, 직교하면 `0`, 정반대 방향은 `-1`이다.

## 데이터 흐름

```text
문장 A -> 같은 embedding model/전처리 -> 벡터 A
문장 B -> 같은 embedding model/전처리 -> 벡터 B
벡터 길이·유한값·영벡터 검증
-> dot과 L2 norm 계산
-> cosine similarity
```

서로 다른 모델의 벡터는 좌표 공간 자체가 달라 직접 비교할 수 없다. 같은 모델이라도 query/passage
구분, pooling, slicing 또는 정규화 방법이 다르면 점수 의미가 달라질 수 있다.

## 현재와 목표의 차이

현재 저장소 검색 DB는 512차원 벡터를 전제로 한다. 선택한 NVIDIA 모델의 native output은 2048차원이다.
NVIDIA 모델 카드는 앞 512차원을 유지할 수 있다고 설명하지만, 잘라낸 벡터를 다시 L2 정규화해야 한다.
실험 B의 목표는 이 동일한 변환을 두 문장에 적용한 뒤 코사인 값을 관찰하는 것이다.

### 왜 `[:512]`인가

벡터 좌표는 일반 배열의 항목처럼 마음대로 골라 써도 되는 값이 아니다. 각 위치는 모델이 학습한 표현
공간의 축이다. 이 모델은 공식적으로 첫 1024개 또는 첫 512개를 남기는 축약만 지원한다. 저장소의
`vector(512)`와 맞는 공식 선택지가 첫 512개이므로 `v[:512]`를 사용한다. 마지막 512개나 무작위
512개는 지원된 축약이 아니다. 이 문서에서는 공개 모델 카드가 구체적인 학습법을 명시하지 않았으므로
이를 특정 학습 기법의 결과라고 단정하지 않는다.

### 자른 뒤 어떤 일이 생기는가

예를 들어 길이가 1인 벡터를 앞부분 `p`와 뒷부분 `q`로 나누면 다음 관계가 성립한다.

```text
||v||² = ||p||² + ||q||² = 1
```

뒷부분에 0이 아닌 값이 있었다면 `q`를 버린 뒤 `||p|| < 1`이 된다. 그래서 다음처럼 재정규화한다.

```text
u = p / ||p||
```

이 연산은 `p`의 모든 좌표에 같은 양수를 곱하므로 512차원 안에서의 방향과 좌표 간 비율은 바꾸지
않고 길이만 1로 만든다. 단위 벡터끼리는 `dot(A, B) = cosine_similarity(A, B)`이므로 내적 기반
벡터 검색과도 일관된 점수를 얻는다.

중요한 한계도 있다. 정규화는 삭제한 1536차원 정보를 복원하지 않는다. 512차원으로 줄이면 벡터
저장 공간과 거리 계산량은 2048차원 대비 4분의 1이지만, 세밀한 의미 구분과 검색 순위가 달라질 수
있다. 따라서 축약 지원은 “품질이 완전히 동일하다”는 보장이 아니며 대표 법률 데이터로 평가해야 한다.

순수 코사인 함수는 분모에서 각 norm을 나누므로 같은 두 truncated vector를 비교할 때 재정규화 전후
코사인 값은 이론상 같다. 그래도 모델 카드가 재정규화를 요구하고, 단위 벡터 저장과 내적 검색을 함께
지원하려면 경계에서 한 번 재정규화하는 편이 계약이 명확하다.

정규화된 벡터는 norm이 1이므로 코사인 유사도가 사실상 내적과 같다. 그래도 구현에서는 입력 검증과
의도를 분명히 하기 위해 일반 공식을 사용한다.

## 해석할 때 주의할 점

- `0.9`가 90% 확률을 뜻하지 않는다.
- 높은 점수가 두 법률 문장이 법적으로 동일하거나 같은 효력을 가진다는 뜻은 아니다.
- 부정어, 숫자, 예외, 법령명처럼 법률상 중요한 차이를 embedding이 충분히 반영하지 못할 수 있다.
- 한 문장 쌍의 점수만으로 검색 임계값을 정할 수 없다. 관련·비관련·경계 문장 평가셋이 필요하다.
- 같은 문장 또는 매우 비슷한 문장은 보통 높은 점수를 기대하지만 model과 전처리별로 분포가 다르다.
- NaN, Infinity, 범위 밖 값, 0 norm은 의미 있는 결과가 아니라 구현 또는 응답 검증 실패다.

## 실험 B에서 확인하는 방법

1. 두 벡터가 모두 512차원인지 센다.
2. 모든 값이 유한한 실수인지 확인한다.
3. 두 norm이 1에 가까운지 확인한다.
4. 두 벡터가 완전히 동일하지 않은지 확인한다.
5. 유사도가 `[-1, 1]` 범위인지 확인한다.
6. 의미가 가까운 두 문장이 양의 높은 값을 보이는지 관찰하되 합격 임계값은 정하지 않는다.
7. 점수가 이상하면 model ID, query/passage 설정, slicing과 재정규화를 먼저 확인한다.

## 검증 방법

단위 테스트에서는 계산을 손으로 확인할 수 있는 작은 벡터를 사용한다.

```text
same:       [1, 0] vs [1, 0]  ->  1
orthogonal: [1, 0] vs [0, 1]  ->  0
opposite:   [1, 0] vs [-1, 0] -> -1
```

영벡터는 분모가 0이므로 예외로 거부한다. 실제 임베딩 테스트에서는 최종 512차원, norm, 유한값과
범위를 함께 검사한다.
