# 작업 계약

복잡한 구현, 저장소 전역 변경, 아키텍처 작업, 다단계 디버깅, 배포, 마이그레이션, 또는 진행 중 범위가
커질 가능성이 있는 작업을 시작하기 전에 짧은 작업 계약을 만든다. 목표·범위·비범위·성공 조건·유지할
기존 동작·외부 작업 허용 범위·보고 수준·새 아이디어 처리 방식을 고정해 재작업을 줄인다. 단순 사실
질문, 작은 읽기 전용 확인, 명백히 범위가 좁은 편집에는 쓰지 않는다.

이미 [docs/exec-plans/active/](exec-plans/active/)에 해당 작업의 실행 계획이 있으면 이 계약을 따로
만들지 않는다 — 그 계획의 완료 조건·체크리스트가 같은 역할을 한다. `docs/PLANS.md` 기준으로 exec-plan이
필요한 규모인데 아직 없으면 이 계약 대신 exec-plan을 새로 만든다. 이 계약은 exec-plan까지는 필요 없는,
한 세션 안에서 끝나는 애매한 작업을 위한 것이다.

**작업 계약과 exec-plan은 outer task(사용자가 요청한 하나의 작업 단위)당 최대 1개다.** calibration
반복, 라벨 정정, metric 재계산, generated report 갱신은 새 task·새 계약·새 decision으로 취급하지
않는다 — 이미 진행 중인 마일스톤의 연장이다. 마일스톤의 **의미 경계**가 실제로 바뀔 때만(예: M4 시작,
M4→M5 전환) 새 계약이나 결정 기록이 필요하다. 이 구분이 없으면 "같은 실수를 다시 하지 말자"는 다짐이
매번 새 문서·새 검증 절차로 번역되어 harness가 계속 무거워진다.

## 계약 만들기

계약을 고정하기 전에 사용 가능한 저장소 컨텍스트(사용자 요청, 기존 계획, 코드, 테스트, 현재 Git 상태)를
확인한다.

본격적인 작업을 시작하기 전에 다음 블록을 짧게 제시한다.

```text
[이번 작업 계약]
목표:
이번에 할 것:
하지 않을 것:
성공 조건:
고정할 기존 동작:
외부 작업 허용: 푸시 / 배포 / 운영 DB (로컬 커밋은 AGENTS.md 커밋 원칙 기본값을 따른다)
보고 수준:
중간 아이디어 처리:
```

간결하게 유지한다. 모든 필드를 사용자에게 채우라고 요구하지 않는다.

- 저장소 관례와 현재 상태에서 추론할 수 있는 되돌릴 수 있는 세부사항은 추론하고 중요한 가정만 말한다.
- 빠진 선택이 제품 방향, 호환성, 보안, 개인정보, 실질적 비용, 운영 데이터, 그 밖의 되돌리기 어려운
  결과를 바꿀 때만 사용자에게 묻는다.
- 요청이 이미 작업을 승인했고 남은 가정이 안전하고 되돌릴 수 있으면 승인을 기다리지 않는다.
- 사용자가 계획만 요청하면 구현하지 않는다.
- 사용자가 구현을 요청하면, 막는 결정이 남아 있지 않은 한 계약을 말한 뒤 계속한다.

## 범위 변경 통제

계약을 현재 마일스톤 경계로 취급한다.

- 새 요구사항은 막는 정합성 문제, 보안·데이터 손실 위험을 고치거나 현재 성공 조건을 무효로 만들 때만
  즉시 반영한다.
- 그 외 아이디어는 후속 TODO로 남기고 현재 마일스톤을 먼저 끝낸다.
- 새 요구사항이 고정된 경계와 충돌하면 충돌을 설명하고 방향을 바꾸기 전에 결정을 요청한다.
- 범위가 바뀌면 전체 계획을 반복하지 않고 영향받은 계약 필드만 다시 말한다.
- 현재 작업과 저장소 문서에서 이미 내린 결정을 보존한다. 보류하거나 거부한 작업을 조용히 다시 꺼내지
  않는다.

## 완료 검증

완료를 선언하기 전에 결과를 모든 성공 조건과 직접 비교한다.

- 완료된 범위, 검증 증거, 편차, 보존한 사용자 변경, 남은 차단 요소를 보고한다.
- 실제로 실행하지 않은 계획된 점검을 완료로 보고하지 않는다.
- 채팅 요약은 짧게 유지한다. 큰 로그나 상세 증거는 지속적 가치가 있거나 사용자가 요청할 때만 적절한
  저장소 산출물에 저장한다.
- 완료 주장에 보류한 TODO를 포함하지 않는다.
- 이번 작업에 실제로 필요했던 최소 프로세스가 무엇이었는지 자기점검해 한 줄로 남긴다. exec-plan·frozen
  contract·SHA 봉인·decision log 같은 무거운 절차를 썼다면 왜 그 무게가 이 작업 규모에 필요했는지 밝히고,
  같은 산출물을 다시 손볼 때(정정·재계산 등) 매번 같은 무게를 자동 반복하고 있지 않은지 확인한다.

## 반복되는 모호 용어 해석

다음 용어가 작업에 영향을 줄 때는 명시적으로 해석한다.

- `전체`: 현재 기능, 전체 미커밋 변경, 또는 전체 저장소
- `검증`: 자동 테스트, production E2E, 또는 제품 품질 평가
- `AI 검색`: embedding 검색, query rewriting, reranking, 또는 답변 생성
- `유지`: API 계약·동작·데이터 보존, 또는 단순 삭제 금지
- `문서화`: 설계 결정, 학습 자료, 실행 기록, 또는 원본 증거
- `커밋/푸시`: 로컬 커밋은 AGENTS.md 커밋 원칙의 기본값(마일스톤 단위 자동)을 따르고, `push`·
  force-push·원격 브랜치·PR·배포·운영 DB는 항상 별도로 확인한다

사용자가 밝힌 목표와 기존 저장소 관례에 맞는 가장 좁은 해석을 우선한다.
