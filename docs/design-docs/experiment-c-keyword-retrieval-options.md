# 실험 C — 키워드 결합 검색 보류 설계

상태: 제안·보류

## 결론

이번 실험에서는 키워드 검색을 구현하지 않는다. 먼저 dense-only 기준선을 고정하고, 이후 같은 평가셋으로
키워드 결합이 실제로 순위를 개선하는지 별도 비교한다. 단순히 질문에 특정 단어가 있으면 법률을 직접
지정하는 규칙은 만들지 않는다.

2026-07-23 실제 기준선은 범위 내 5문항에서 Law@1 `1.0`, Article Recall@3 `0.8`, Recall@5
`0.8`, Recall@10 `1.0`, MRR `0.82`였다. top 5는 top 3에서 놓친 저작권법 제1조를 복구하지
못했지만 top 10은 복구했다. 따라서 지금 필요한 것은 top K 숫자만 바꾸는 작업이 아니라, 검색 방식별
기여도를 분리해서 비교하는 실험이다.

## 검토한 선택지

### 1. 질문 키워드로 법률을 직접 지정

예: `태양광`이 있으면 신재생에너지법에 가산점을 준다. 작은 예제에서는 잘 맞아 보이지만 표현이 바뀌거나
새 법률이 추가되면 규칙이 깨지고, 평가 질문을 외운 구현이 되므로 채택하지 않는다.

### 2. 로컬 lexical 검색과 dense 검색을 RRF로 결합

후속 실험의 권장안이다. 법률명·조문 번호·정확한 용어에 강한 lexical 순위와 의미가 비슷한 표현에 강한
dense 순위를 각각 계산하고 Reciprocal Rank Fusion(RRF)으로 합친다.

```text
RRF score = 1 / (60 + dense_rank) + 1 / (60 + lexical_rank)
```

초기 lexical 방식은 외부 서비스가 필요 없는 한국어 문자 n-gram 또는 BM25 후보를 비교한다. RRF 상수
`60`과 tokenizer 선택은 확정값이 아니라 평가 대상이다. 결합 뒤에도 dense·lexical 원래 순위와 점수를
모두 남겨 어느 방식이 후보를 올렸는지 추적한다.

### 3. production PGroonga 재사용

운영 검색과 가까운 장점이 있지만 로컬 실험 C가 DB 설치와 마이그레이션에 의존하게 된다. 격리된 기준선
실험에는 사용하지 않고, 운영 검색 검증 단계에서 비교한다.

### 4. 외부 reranker 사용

별도 모델·비용·지연·provider 실패 조건이 생긴다. lexical 결합의 효과를 먼저 측정한 뒤 독립 실험으로
검토한다.

## 후속 구현 게이트

- 현재 `evaluation-questions.json`과 corpus SHA-256을 그대로 사용한다.
- dense-only와 hybrid 결과를 서로 다른 산출물로 기록한다.
- Law@1과 Recall@10을 기준선보다 낮추지 않는다.
- 목표는 Article Recall@3 `0.8` 초과와 MRR `0.82` 초과다.
- 질문별 raw chunk, article rank, dense rank, lexical rank, 결합 rank를 보존한다.
- 평가셋에만 맞춘 법률명·단어 하드코딩은 금지한다.

## 결정 기록

- 2026-07-23: dense-only 실제 결과를 먼저 고정하기 위해 구현을 보류했다.
- 2026-07-23: 후속 기본안은 로컬 lexical 검색과 dense 검색의 RRF 결합으로 정했다.
