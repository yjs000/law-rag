# B-017 반복 검토 기록 설계

## 목적과 경계

실제 법률 답변을 사람이 읽고, 결론의 명확성·쉬운 말·다음 행동·근거 표시를 반복 판정한다. 날짜별 원자료를 보존하면서 여러 날의 관찰을 하나의 누적 review에서 비교한다. 이 작업은 평가 기록의 구조를 정리하며 답변 코드, 검색, 모델, DB 스키마는 바꾸지 않는다. 사람의 주관적 판정은 기록하되 자동 점수로 성공을 단정하지 않는다.

## 선택한 방식

날짜별 review를 계속 늘리는 방식은 판단이 흩어진다. 원자료와 review를 하나로 합치는 방식은 출처와 비결정적 출력의 차이를 잃는다. 사용자는 원자료를 보존하고 누적 review와 회차별 판정을 분리하는 방식을 선택했다.

`apps/api/evaluation/b017/` 아래에 `raw/`(날짜별 원자료), `rounds/`(회차별 관찰), `review.json`(누적 판단), `README.md`(다음 회차 기록 절차)를 둔다. 10월 21일의 원문 JSON과 10월 27일의 DB 관찰 JSON은 원자료로 이동한다. 두 날짜의 기존 review는 회차별 기록으로 옮겨 내용과 출처를 보존하고, 누적 review에는 반복되는 문제, 새 문제, B-017 범위 판단, 검증 대기 항목을 합친다. 이후 회차는 원자료와 회차별 기록을 추가하고 누적 review만 갱신한다.

## 판정 원칙

서로 다른 질문 수와 반복 실행 수를 별도로 센다. 10월 21일은 질문 6개 중 답변 5개·실패 1개, 10월 27일은 질문 1개를 4회 실행한 기록이다. 웹 렌더링·인용 원문·법적 수치는 확인한 범위까지만 판정한다. 결론 누락, 전문용어, 내부 ID 노출, 읽기 순서는 B-017에 포함한다. 수치·인용 정확성은 B-017 변경의 안전 검증으로 추적하되, 원인이 검색 품질이면 별도 후속 작업으로 제안한다. 503 실패와 후속 질문의 상태 연결도 원인 확인 전에는 범위를 넓히지 않는다. 각 판단은 관찰과 이유를 붙인다.

## 완료 확인

모든 기존 관찰이 새 구조에서 출처와 함께 찾아지고, JSON을 파싱할 수 있으며, 누적 review가 두 날짜의 차이와 범위 판단을 담는다. 참조 경로를 확인하고 `git diff --check`를 통과한다.

## 결정 기록

- 2026-10-27: 사용자가 날짜별 원자료 보존과 누적 review·회차별 판정 분리를 선택했다. 동일 질문의 반복을 독립 질문으로 과대계산하지 않고 주관적 검토를 이어 가기 위해서다.
